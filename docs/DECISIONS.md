# 关键决策

## 1. 采用订阅源，而不是写入用户个人日历

订阅源可由任意日历客户端消费，不依赖用户的 Mac、Codex 或账号凭据持续在线。

## 2. V1 使用豆瓣“即将上映”页面

该页面直接按中国大陆上映日期列出国产片与进口片，当前能同时识别《蜘蛛侠：崭新之日》和《奥德赛》。抓取实现被隔离在 `fetch.py` 与 `parser.py`，后续可增加猫眼或官方来源适配器。

GitHub Actions 机房 IP 可能被来源页拒绝。直连失败时通过 Jina Reader 的 HTML
模式读取同一页面；来源 ID、字段结构与合并语义保持不变。

## 3. 来源 ID 决定 UID

ICS UID 使用 `douban-{subject_id}@mainland-movie-calendar`。改名或改档不会改变 UID，因此订阅客户端会更新原事件。

## 4. 不在首次缺失时删除或撤档

来源页面可能短暂故障或分页变化。只有尚未上映的影片连续三次抓取缺失，才标记“已撤档，待定”；项目永不自动删除日程。

## 5. GitHub Actions 提交生成物

`data/movies.json`、`docs/calendar.ics` 与 `docs/index.html` 保存在仓库中，便于审计每次档期变化，也可由 GitHub Pages 直接托管。

## 6. 只有具体日期才进入订阅

来源有时只给出“2027 年 2 月”之类的月份窗口。项目会跳过这些项目，直到来源给出具体日，避免把猜测写进用户日历。
