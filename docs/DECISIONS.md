# 关键决策

## 1. 采用订阅源，而不是写入用户个人日历

订阅源可由任意日历客户端消费，不依赖用户的 Mac、Codex 或账号凭据持续在线。

## 2. V1 使用豆瓣“即将上映”页面

该页面直接按中国大陆上映日期列出国产片与进口片，当前能同时识别《蜘蛛侠：崭新之日》和《奥德赛》。抓取实现被隔离在 `fetch.py` 与 `parser.py`，后续可增加猫眼或官方来源适配器。

GitHub Actions 机房 IP 可能被来源页拒绝。直连失败时通过 Jina Reader 的 HTML
模式读取同一页面；来源 ID、字段结构与合并语义保持不变。

## 3. 来源 ID 决定 UID

ICS UID 使用
`douban-{subject_id}@mainland-movie-calendar.ichigokk.github.io`。改名或改档不会
改变 UID，因此订阅客户端会更新原事件；仓库专属域名也避免与用户已有日历冲突。

## 4. 不在首次缺失时删除或撤档

来源页面可能短暂故障或分页变化。只有尚未上映的影片连续三次抓取缺失，才标记“已撤档，待定”；项目永不自动删除日程。

## 5. GitHub Actions 提交生成物

`data/movies.json`、`docs/calendar.ics` 与 `docs/index.html` 保存在仓库中，便于审计每次档期变化，也可由 GitHub Pages 直接托管。

## 6. 只有具体日期才进入订阅

来源有时只给出“2027 年 2 月”之类的月份窗口。项目会跳过这些项目，直到来源给出具体日，避免把猜测写进用户日历。

## 7. Docker 常驻服务作为自托管主路径

NAS/服务器容器内运行更新循环和静态 HTTP 服务。电影数据更新不依赖用户的 Mac、
Codex 自动任务或桌面会话是否解锁；GitHub Actions 不再定时生成，Pages 只保留为公共
演示和备用地址。

## 8. 数据卷与程序镜像分离

状态文件、生成的 ICS 和订阅页写入 `/data` 持久卷，程序和内置种子数据保存在只读镜像。
容器升级不会丢失来源 ID、历史档期或缺失次数。

## 9. 抓取失败时保留最后有效输出

服务启动时先提供镜像内置或数据卷中的上一份有效日历。后台抓取失败只会让健康状态变为
`degraded`，不会用空文件覆盖日历；服务按更短间隔重试。
